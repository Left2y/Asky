# Asky 数据、记忆与提醒设计

更新日期：2026 年 10 月 9 日。状态：数据职责与生命周期设计；持久化结构及 Pi 历史整合待原型验证。

数据默认留在设备上。只有被允许用于 AI 的必要上下文才发送到用户配置的模型；本地存储不表示离线推理。产品行为见 [PRD](PRD.md)，模型与会话整合见 [Agent Runtime](agent-runtime.md)。

## 数据归属

| 数据 | 权威来源与职责 | 原生读取方式 |
| --- | --- | --- |
| 日历、提醒、联系人、Notes | 系统应用继续为真实记录来源 | 授权范围内查询与有限快照，不全量复制私有数据库 |
| 活动、记忆、执行记录、提醒计划、授权设置 | 原生 LocalStore，SQLite 与全文索引 | 分页、过滤和局部更新 |
| 对话历史 | Pi 与 SQLite 的唯一权威方案必须经 M0 固化 | UI 使用分页显示投影，不加载全部 Runtime 消息 |
| 图片附件与大输出 | 独立本地文件，数据库保存引用与生命周期 | 使用时读入、显示缩略图 |
| API Key 与接入凭据 | Keychain | 仅调用方按需读取，不进入业务导出或日志 |

首版检索采用 SQLite 全文索引、项目与实体关联；不要求向量数据库、云端 embedding 或下载本地大模型。文件名搜索交给 Spotlight，而不是为整盘内容另建全文索引。[SQLite FTS5](https://www.sqlite.org/fts5.html)、[Apple Spotlight](https://developer.apple.com/documentation/foundation/spotlight)

SQLite 存储落盘不代表可以无限缓存查询结果。连接、页缓存、索引更新、游标与结果集也需要有界管理，详见 [资源生命周期](resource-lifecycle.md)。

## 对话与 Pi 的整合决策

当前优先验证 Pi SessionManager 管理运行会话，SQLite 保存 UI / 检索投影、关联和产品数据的方式。投影必须可从选定的权威历史恢复，不能成为另一套互相矛盾的完整对话。

M0 必须核实：

1. 明确消息、分支、压缩摘要和完成状态的唯一权威来源，以及进程退出前保存的顺序。
2. 原生界面在 Pi 未运行时可以分页查看历史；切换会话不加载所有消息。
3. 宿主崩溃、Pi 崩溃和投影未完成时能够恢复，不重复消息或重放写入。
4. 恢复只装配任务需要的有界上下文；长会话文件解析也纳入内存测量。
5. 图片能外置并按需参与请求，清理附件后原始会话、投影、压缩摘要和引用不残留可恢复原图。
6. 对话删除、导出和授权撤销覆盖所有持久化载体，不只删 SQLite 的显示记录。

若 SDK 的会话模型不能满足这些条件，应验证受控会话段、导入或替代存储适配方式，再决定实现。不能先宣称 SQLite 与 Pi 都保存完整历史、以后再同步。Pi SessionManager 对运行上下文的权威规则需遵守，直接改 agent 内存消息不等同于修改已保存历史。[Pi Session storage](https://pi.dev/docs/latest/sdk)

## 记忆层与接口

| 层 | 内容 | 保留目的 |
| --- | --- | --- |
| 当前上下文 | 当前选择文字、截图、有限工具结果 | 完成本次任务 |
| 活动记录 | 应用内搜索、对话与操作来源 | 追溯行为与提炼来源 |
| 情景记忆 | 最近推进的项目、讨论与决定 | 找回“上次那个想法” |
| 长期记忆 | 明确偏好、稳定习惯、已确认关系 | 减少重复解释 |

MemoryRecord 至少包含内容、类型、来源标识、时间、适用项目或实体、确认状态、替代关系与来源授权信息。事实、明确偏好和推测应有不同状态，用户可查看依据、编辑、删除与暂停提炼。

当前检索应返回相关片段及来源，而非完整数据库。用户明确纠正优先；被替代记录可以追溯，但不再作为当前事实。关系或对象歧义先询问，不能因“奶奶”等自然语言称呼擅自绑定联系人。

Agent 写入记忆有两条路径：

- **对话中明确要求**：`memory_save` 保存用户明确要求记住的内容（来源为「对话中保存」，标记已确认）；`memory_correct` 和 `memory_forget` 按用户的纠正修改或删除已有记忆。三者在用户本轮明确要求时直接执行、不弹确认（记忆可在设置中查看和撤改），模型自行推断的写入只返回建议。这些工具不向外部 MCP 开放。
- **自动提炼与修正**：每轮对话结束后，若记忆数据源已启用、未暂停提炼且已配置模型，原生端从提炼队列取最多 3 个对话，把上次提炼之后的新消息与允许 AI 使用的已有记忆（编号 M1…，最多 60 条）发给模型。模型返回三类结果，均直接生效：新记忆存为未确认（推测类在上下文中标注「推测」）；被对话推翻或纠正的旧记忆改写为新内容，旧记录标为已替代并可追溯，新记录追加该对话为来源；不再成立的记忆删除（固定的除外）。只处理输入中出现的编号，同一条每轮最多处理一次。模型调用失败的来源重新入队；来源在提炼期间被删除或撤销提炼授权时丢弃结果。
- **定期清理**：每次提炼前清理过期记忆。记忆交给模型使用时记录使用时间；未确认记忆 60 天内未被更新或使用、情景记忆（项目、决定）180 天内未被更新或使用即删除。固定的记忆和已确认的事实、偏好不会自动清理。

## 来源与外发限制

来源设置分别控制读取、AI 使用、自动提炼与后台提醒。Chrome 标签搜索缓存与剪贴板历史不自动成为长期记忆；浏览历史和网页行为不进入首版采集范围；短信原文不做持久采集，仅在用户单独开启后由后台 AI 提炼成短事项（见下文）。

每条摘要和派生记忆继承来源限制。混合多个来源时不能通过摘要绕过其中禁止外发的来源；组装模型上下文时仍须重新检查有效授权。撤权后取消未执行的访问和请求，已发送的数据不能描述为可以从远端撤回。

记忆提炼以允许来源为候选。默认不会为每次搜索、每次复制或每条事件启动模型；本地可先记录来源与显式偏好，模型提炼进入有界队列，在下次 AI 使用时分批处理。用户未启用后台 AI 时，复杂提醒可能延后，这一行为应在设置中说明。

## 删除、过期与保留

以下磁盘默认值来自 [PRD 建议默认值](PRD.md)，与内存缓存预算无关。

| 数据 | 默认保留与清理 |
| --- | --- |
| 剪贴板 | 启用后保留 30 天；容量建议 200 MiB，先清理未固定旧项；固定项手动删除 |
| 活动记录 | 搜索与操作保留 30 天 |
| 完整对话与独立记忆 | 保留至用户删除；完整不代表全部常驻内存 |
| 截图 | 默认临时，任务结束清理原图；主动保留的附件跟随对话 |
| 当前工具快照与上传缓冲 | 请求或任务结束释放；只保留允许的必要结果 |
| 系统计划 | 事件变更、已处理、禁用类别或依据删除时重新校验或取消 |

固定剪贴板占满容量时不能偷偷删除固定内容或继续无限存储；建议停止新增并提示用户管理容量，此细节在原型中验证。

主动删除来源时，清理仅由该来源形成的记忆、索引、摘要、附件及提醒依据，并设置必要的删除标识，防止未完成提炼任务从残留内容重建。用户主动固定的独立记忆可按界面说明保留，但展示来源已删除。

自然到期仅清理原始活动，保留已获准独立保存的记忆和最小来源元数据，并标记来源已过期。不能把到期与用户主动删除混为一谈。删除授权时明确处理已保存记忆的保留选择，失去有效依据的提醒取消。

删除与索引更新需要可恢复的清理流程；覆盖 Pi 历史、SQLite、附件、显示缓存和待处理队列。逻辑删除不等于承诺底层磁盘安全擦除，也不等于数据库文件立即缩小。

## 情境提醒与后台调度

Context Scheduler 监听已授权的数据变化、临近检查点、相关记忆变化以及系统恢复，先运行确定性规则，不持续模型轮询。队列按事件与原因去重、合并与淘汰过期候选，不保存无限事件快照。

| 场景 | 确定性部分 | 必要条件 |
| --- | --- | --- |
| 日程冲突 | 时间重叠、相邻日程间隔、有效路线与交通偏好 | 不自动移动原日程 |
| 出行准备 | 起终点、目标时间、路线 ETA、交通方式、缓冲 | 缺起点、地点或 ETA 时只提示检查路线，不编造精确时间 |
| 重要日期 | 临近日期、允许记忆、已处理状态 | 生日送礼必须有关系或既往意图依据，无物流数据不承诺到货 |

ReminderPlan 至少保存事件标识、原因、依据引用、触发时间与状态。默认生日提前 7 天检查，出行缓冲建议 10 分钟；建议每天最多 2 条、09:00–21:00 无声交付。用户明确设置的定时提醒不受智能建议数量限制。

### 后台 AI 建议

用户开启「后台 AI 判断」并配置模型后，每次重新校验时把未来 7 天的日程、未完成提醒事项（按截止时间排序，最多 60 条）和允许 AI 使用的相关记忆，以短编号（E/T/M）发给已配置的模型。模型只返回日历本身做不到的建议：需要提前准备的事项、日程与待办或记忆之间的关联与矛盾、临近截止却未安排时间的待办；没有值得提醒的事返回空。

每条建议必须锚定输入中的日程或待办，依据编号逐条校验，未知编号丢弃；触发时间不早于当前、不晚于锚定日程开始和 7 天视野。建议以 `insight` 类别进入同一 Scheduler，排在确定性规则之后，共享去重、每日上限、09:00–21:00 窗口和“关闭此类”。输入指纹不变时 6 小时内不重复调用，两次调用至少间隔 10 分钟；锚定对象变更或删除后缓存建议失效并取消。后台调用不弹出 Keychain 交互，读不到 Key 时跳过。短信内容默认不在输入范围内。

用户另外开启“让后台 AI 读取最近 30 天的短信与 iMessage”并授予完全磁盘访问后，ToolService 的 `MessagesHistoryReader` 以只读方式打开 `~/Library/Messages/chat.db`，读取最近 30 天至多 300 条消息（含用户自己发出的，标记为“我”），跳过表情回应与系统项。macOS 没有读取短信的公开接口，这是唯一途径，因此该能力不兼容 App Store 沙盒。读取后立即脱敏：含验证码等字样的消息整条丢弃，8 位以上数字只保留后 4 位，每条最多 300 字；发送者优先显示通讯录姓名，否则手机号只显示尾号、邮箱只保留首字母和域名。`attributedBody` 按 typedstream 结构手工解析，不反归档对象。

短信分两步使用，避免单次请求过大。第一步 `MessageTriage` 只处理水位线（已读过的最大消息 ROWID）之后的新消息，按时间顺序每批约 2,500 字，附带同一会话前 3 条消息作上下文，请模型摘出仍需行动的事项（每条不超过 40 字，可带截止时间），并可把已完成、取消的旧事项标为已解决。每批成功后水位线前移，所以每条消息只发送一次；单轮最多 6 批，首次开启时其余历史在后续轮次读完，失败时从第一未读批继续。事项至多保留 30 条，超出 30 天自动丢弃。第二步 `SmartAdvisor` 只收到这些事项（S 编号），不再接触短信原文；事项可作为建议锚点，消失后对应缓存建议失效。事项摘要与水位线保存在本地设置中，短信原文不写入本地数据库或记忆；关闭该开关时清空事项与水位线。

默认后台模型唤醒关闭：本地冲突检查、已形成的路线计划与系统通知照常运行；需要模型的新复杂建议等待下一次明确 AI 使用，或由用户单独启用后台 AI。不得为了按需省内存而声称所有智能建议仍可即时产生。

地图请求只发送必要地点，单独启用，不持续采集位置。计划由系统本地通知交付；主应用退出后仍可交付已注册通知，但不会发现新变化。恢复、时区变化、事件修改或删除时重新校验，取消过期计划。[Apple 本地通知](https://developer.apple.com/documentation/usernotifications/scheduling-a-notification-locally-from-your-app)
