# Asky Agent Runtime 设计

更新日期：2026 年 10 月 9 日。状态：架构设计；Pi 集成、启动占用和系统调用尚未运行验证。

本设计用可替换的 Agent 内核处理模型与工具之间的多步任务。原生启动器、系统工具、记忆存储、权限和提醒调度独立于该内核。产品行为见 [PRD](PRD.md)，整体进程图见 [框架](framework.md)。

## 选型与依赖

优先验证 @earendil-works/pi-coding-agent SDK：它已有会话、上下文压缩、流式事件和 Extensions 机制，可在本地 Node.js 或 Bun 进程中嵌入。首轮原型建议采用 Node.js 辅助进程；随应用携带运行时的形式、启动成本、签名与最终分发方式在 M0 核实，用户不应被要求先安装全局 Pi。[Pi SDK](https://pi.dev/docs/latest/sdk)

| 路线 | 获得什么 | 当前处理 |
| --- | --- | --- |
| Pi Coding Agent SDK | Agent 循环以及会话、资源加载和 Extensions | 优先原型验证 |
| Pi Agent Core | 更小的 Agent 循环、工具与流式事件 | 不能直接视为完整 Extensions SDK；会话与加载机制需要补齐 |
| 纯 Swift Runtime | 减少跨语言辅助进程 | 验证失败后的备选，需要自行维护模型协议与 Agent 循环 |

选装扩展、关闭工具和移除运行依赖是不同动作。当前 SDK 的依赖清单含 pi-agent-core、pi-ai、pi-tui、pi-mcp、pi-codemode 等；不用终端界面也不能据此声称没有 pi-tui 依赖。原型应记录实际安装版本与依赖树，不把仓库 main 的版本号当成最终发布锁定版本。[SDK 包定义](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/package.json)、[Agent Core](https://github.com/earendil-works/pi/tree/main/packages/agent)

Pi 是可替换基础设施。Swift 业务模块通过 AgentHost 接口接入，不直接依赖 Pi 类型；不能把个人记忆、系统权限与调度逻辑迁入 Pi 扩展后才可运行。

## 进程职责与模型接入

| 归属 | 职责 |
| --- | --- |
| SwiftUI / AppKit 主应用 | 界面、AgentHost、辅助进程管理、原生确认与用户设置 |
| Pi 辅助进程 | 模型请求、Agent 循环、工具编排、会话运行状态与事件 |
| Swift ToolService | 系统授权、参数与目标检查、写入策略、执行、去重及回读 |
| Native LocalStore / Memory Engine | 产品持久化、授权上下文检索、来源与删除生命周期 |

首版优先 OpenAI-compatible Chat Completions；用户配置 API 地址、模型名与 Key。连接检查分别验证文本流式回答、图像输入和工具调用，不把 HTTP 连接成功视为全部能力可用。缺失能力只关闭对应功能，不能阻塞本地入口。

Key 存在 Keychain。模型请求确需凭据时，AgentHost 只为选定模型提供必要的进程内使用凭据；不能写进普通 Pi 配置、命令行参数、日志、SQLite 或导出，也不能交给系统工具与外部 MCP。具体凭据注入路径需要在 M0 验证，避免框架默认存储产生第二份持久化密钥。

用户输入的凭据必须作为字面值处理，不能交给框架解释为环境变量插值或 !command。默认关闭模型缓存保温、空闲自动模型请求与无必要的 provider 后台刷新，避免 60 秒保留窗口内仍产生后台 AI 调用。

Pi 的 provider 适配与兼容端点需逐项验证，尤其是流式工具参数、错误结束、图像、思考能力和取消。BYOK 不表示完全离线推理；只有启用来源中的必要片段可以外发。[Pi Provider 扩展](https://pi.dev/docs/latest/custom-provider)

## 扩展与工具集合

Asky 使用应用专属配置、资源目录和自定义 ResourceLoader，只加载明确列出的资源；不使用默认工作目录发现机制读取用户全局或项目的 .pi、.agents、AGENTS、Skills、Prompts 与凭据。路径布局与打包清单待 M0 固化。

| 自有扩展组 | 能力 | 边界 |
| --- | --- | --- |
| 系统工具 | 注册允许的日历、提醒、Notes、联系人、Chrome、Shortcuts 和 Messages 草稿能力 | 转交原生 ToolService；不直接读取系统私有数据库 |
| 个人上下文 | 获取允许的记忆片段，提交记忆提炼建议 | 原生存储与来源策略决定读写，不拥有整库访问权 |
| 原生交互 | 进度、澄清、预览、确认与状态事件 | 由 SwiftUI 呈现，不能伪造用户确认 |

首版不安装无关扩展，不自动下载插件，不建立第三方插件商店。包或资源可使用显式清单筛选；未声明的资源不得因默认配置而进入会话。[Pi Packages](https://pi.dev/docs/latest/packages)

默认不注册或暴露编码 read / write / edit / bash、自由 Shell、codemode、tool_search 或子 Agent 入口。SDK 不自动加载 CLI 的所有内建扩展；如果某项确有产品用途，应另行显式登记。用户直接输入的终端命令仍走原生 Direct Actions，而不是借 Pi 的 bash 工具执行。

工具允许列表不能只限制模型表面可见的工具：codemode / deferred 等暴露方式可能通过其他工具到达注册能力。应检查全部可达入口、输入前缀和内嵌命令路径，并在原生执行层再次检查权限。Pi 扩展与进程共享系统权限，不构成操作系统沙箱；V1 仅携带由项目维护的可信扩展。[Pi Extensions](https://pi.dev/docs/latest/extensions)

## 原生通信与事件契约

优先验证由项目维护的薄 TypeScript 宿主包装 SDK，以受控本地通道连接 AgentHost。stdio JSONL 是候选承载方式，Pi 官方 RPC 是对照方案；线格式、版本握手、消息大小、附件传递与崩溃重连在 M0 评估后锁定，不能把以下概念接口当成已经实现的协议。[Pi CLI Integration](https://pi.dev/docs/latest/cli-integration)

| 消息方向 | 最低需求 |
| --- | --- |
| 原生到 Runtime | 建立或恢复会话、提交文本及附件引用、取消、澄清回复、配置当前模型与允许能力 |
| Runtime 到原生 | 文本增量、完整消息、工具调用、工具进度、澄清请求、任务结束、错误与退出状态 |
| 原生工具往返 | 请求标识、会话与任务关联、结构化参数、结果状态和目标引用 |
| 确认交互 | ToolService 产生绑定具体操作的请求，由原生 UI 提交可信决定；Runtime 只接收执行结果 |

辅助进程只能通过受控连接访问宿主工具，不能连接到未授权来源。stdio 若被选用，stdout 只承载协议，诊断走 stderr 并脱敏；写入队列、背压、乱序事件、最大帧与附件文件访问规则需验证。大图不应在多层协议和日志中反复保存 Base64 副本。

完成状态以宿主任务与实际工具结果为准。在 SDK 层，agent_settled 比单次 agent_end 更适合判断自动继续是否结束；宿主仍需确认没有工具或确认请求待处理。[Pi SDK 生命周期](https://pi.dev/docs/latest/sdk)

## 辅助进程状态机

以下空闲时长为建议默认值，独立于“AI 能力是否已配置”的设置。

| 当前场景 | 行为 |
| --- | --- |
| 登录或手动启动 Asky | 不启动 Pi，也不因已配置模型而预热 |
| 搜索、计算、剪贴板、原生规则与外部 MCP | 不启动 Pi |
| 进入 AI 界面、查看历史 | 原生层读取分页历史，不启动 Pi |
| 用户明确提交 AI 请求 | 启动一次辅助进程、完成握手和资源加载，立即显示启动状态 |
| 同时到来的启动请求 | 合并启动，避免产生多个辅助进程；任务按当前会话排队 |
| 运行、工具执行、等待操作确认 | 保持运行，不启动空闲退出倒计时 |
| 等待普通补充输入 | 保存对话与检查点，可按空闲规则退出；再次提交时恢复 |
| 任务结束且无待处理工作 | 开始 60 秒空闲倒计时；新请求取消倒计时 |
| 空闲到期 | 保存可恢复状态、关闭连接与扩展资源、真正退出辅助进程 |
| 进程崩溃或连接断开 | 显示失败或结果待核实；本地入口继续可用，不自动重放写入 |
| 退出主应用 | 取消剩余模型工作，保存已完成步骤并终止受管理辅助进程；不留下孤儿进程 |

关闭会话或调用 dispose 不等于 Node 进程已经退出。验收必须检查 OS 进程与子进程，而非只检查模型请求停止。

## 任务规则、取消与恢复

建议每个会话同一时刻只运行一个任务，自动工具循环最多 8 轮，达到上限后展示已完成步骤并请求用户继续。这些初值待原型校准；不允许无限自动循环。读取可以在预算内并行，写入由 ToolService 串行执行。

任务状态至少区分启动中、执行中、等待补充、等待确认、完成、取消、失败和结果待核实。确认绑定目标、参数与请求标识；任何参数修改使旧确认失效。拒绝不能重试成自动批准。

隐藏面板只卸载显示资源，不取消实际任务；点击“停止”才取消。取消传递到模型、工具和嵌套工作，但不回滚已完成写入。Apple Events 等操作如果无法确定取消时点，应先回读，再报告实际结果。

会话恢复与任务恢复是不同能力。恢复历史不能自动重放旧工具调用；超时、崩溃或断开后的写入先通过原生执行记录与系统结果核实，确实未执行且仍获授权时才能继续。

## 会话、上下文与后台工作

Pi SessionManager 与原生 SQLite 不得各自成为两份独立的完整对话事实来源。优先验证“Pi 管理运行会话，SQLite 保存产品检索与显示投影、执行记录和长期记忆”的设计；实际持久化权威、投影同步、短上下文恢复和附件外置方式属于 M0 必须完成的决策。[数据设计](data-and-memory.md)

上下文从必要对话片段、授权记忆与有限工具结果组装，不读取整个历史库。Pi 压缩不自动等同于附件被删除或原始会话不再占内存；需用长会话与大图验证恢复过程，必要时使用有界会话段或受控导入，而不是无限加载历史。

后台模型唤醒默认关闭。确定性事件检查照常运行；需要模型的记忆提炼与复杂建议进入有界、可合并的待处理队列，下次明确使用 AI 时按预算处理，不抢占当前任务。用户单独开启后台 AI 后，也只能对允许来源的有效候选启动一次短任务。

M0 验证项目与通过条件见 [实施与验证](implementation-and-validation.md)；资源释放与预算见 [资源生命周期](resource-lifecycle.md)。
