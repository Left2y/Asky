# Asky 资源生命周期与性能设计

更新日期：2026 年 10 月 9 日。状态：工程约束与测量方案；尚无实际内存、启动和功耗测量结果。

全天候运行要求资源有明确归属、容量上限和释放时机。SwiftUI 不保证低占用，退出 Pi 也不能替代原生资源管理。本设计同时覆盖堆、图像与窗口资源、数据库、任务和辅助进程。

## 资源作用域

| 作用域 | 可以持有 | 结束条件 |
| --- | --- | --- |
| 应用 | 设置、服务句柄、授权状态、必要监听、小型有界缓存 | 退出、禁用能力或撤权 |
| 面板与页面 | 当前结果、有限消息、缩略图、解析与布局状态 | 页面切换或隐藏；卸载重视图与页面状态 |
| 搜索 | 当前查询标识、游标、有限批次结果 | 新查询、隐藏、取消或完成 |
| 任务 | 必要上下文、临时附件引用、工具状态、取消令牌 | 完成、拒绝、取消或失败 |
| 磁盘记录 | 原图、历史、全文索引、大输出、检查点 | 保留期限、用户删除、清理策略 |

常驻服务保存标识与小状态，不通过单例、闭包或全局 ViewModel 持有所有图片和历史。隐藏 NSPanel 不保证其中视图或状态已经释放，应显式卸载重内容；不能只依赖 onDisappear 推断清理完成。

任务层与页面层分离：隐藏界面取消搜索和预览，不取消已经执行的 AI / 系统操作。工具确认与活动任务仍由任务作用域持有必要状态。重新打开面板时读取分页状态，不重新执行旧操作。

## 初始预算

下表是建议默认值，用于实现资源的有界性，不是已测得的占用或总进程内存承诺。

| 项目 | 初值 | 实现与测量 |
| --- | --- | --- |
| 解码图片与缩略图缓存 | 32 MiB | 按实际解码成本记账，LRU 淘汰，包含应用控制的共享图片缓存 |
| 文本与元数据缓存 | 16 MiB | 按字节记账，不含可无限增长的完整数据库 |
| 历史首批 | 最近 40 条 | 向上分页 |
| 消息内存窗口 | 最多 120 条 | 超出移除离屏页；重新滚动按需读取 |
| Pi 空闲窗口 | 60 秒 | 没有任务、工具或操作确认后才计时 |

消息数量限制仍不足以限制单条超长文本，应为大消息、Markdown 解析、搜索摘要和工具输出设置字节上限、延迟渲染或文件化方式。原图、在途解码、上传缓冲和 GPU / 窗口资源不自动包含在上述缓存数值内，必须单独测量和限制并发。

图片解码建议首轮最多 2 个并发工作，索引与提炼各保留一条有界工作队列；这些是工程建议，实际批次大小和峰值在 M0 / M1 校准。系统写入无论预算如何都由 ToolService 串行执行。

不先承诺“原生常驻低于某个 MB”或“Pi 只占几十 MB”。原型记录当前设备、数据规模、版本和预热状态后，再定义总 footprint 的可接受区间。

## 各类资源的加载与释放

| 资源 | 加载规则 | 释放规则 |
| --- | --- | --- |
| 截图原图 | 用户主动选择；落临时文件，按需要读入 | 请求完成释放解码与上传缓冲；任务结束删除默认临时原图并清理持久化副本 |
| 剪贴板图片 | 原图存磁盘，列表加载显示尺寸缩略图 | 离屏释放非必要解码图；保留与删除遵循磁盘策略 |
| 历史消息 | 有界分页，不把 Lazy 列表误当数据已分页 | 切换与隐藏卸载消息页、Markdown 树、布局及缩略图 |
| Chrome | 当前搜索取得标题、URL 与目标标识 | 查询结束清本次快照，不积累网页正文或浏览历史 |
| 搜索结果 | 每批仅取有限结果，最新查询可写回页面 | 新输入取消旧查询；返回前检查查询标识以丢弃迟到结果 |
| 全文索引 | SQLite 落盘，按需查询，更新分批 | 游标与 statement 及时关闭，不把整库复制成 Swift 数组 |
| 模型上下文 | 选择必要片段并限制工具结果 | 请求结束释放序列化副本；Runtime 退出释放进程内状态 |
| 工具与终端输出 | 小结果直接展示，大输出流式写入受控文件 | 只保留可见片段和必要尾部；删除记录联动清文件 |
| 监听与计时器 | 只在能力启用时注册，回调保存必要标识 | 禁用、撤权、任务结束或退出时移除；重连避免重复注册 |
| 工作队列 | 合并同事件候选、设置容量、任务可取消 | 完成出队、过期淘汰；取消不能让旧回调重新填满缓存 |

## 图片、缓存与复制成本

使用 Image I/O 从源文件直接生成按目标尺寸与显示 scale 计算的缩略图，避免完整解码后再缩小。一张 3840×2160 的 8-bit RGBA 图像，仅像素缓冲就约 31.6 MiB，不能按 PNG 文件大小估算解码内存。[Apple 图像内存说明](https://developer.apple.com/videos/play/wwdc2018/416/)

同一附件尽量共享文件引用，避免原图、NSImage、CGImage、Data、Base64、协议字符串和历史消息中长期保留多份内容。模型必须使用完整图像时按需读取，但不能为省内存无声降低模型输入到无法阅读；图像尺寸、上传上限与清理规则需要在能力验证中核实。

NSCache 可以用于可丢弃资源，但 totalCostLimit / countLimit 不是严格上限。项目应自行记录缓存成本并在准入时淘汰，不把它当进程总内存限制。GPU、临时缓冲、框架缓存与在途任务仍需测量。[Apple NSCache](https://developer.apple.com/documentation/foundation/nscache/totalcostlimit)

内存压力到来时优先清可重建图片、非可见页面与元数据缓存，减少解码和索引并发，暂停非必要后台任务；不能等系统通知才首次执行容量控制，不能删除用户持久数据或中断无法核实的写入。

## 数据库与后台成本

控制连接数量、每连接页缓存与查询批次，短事务结束后释放游标，不让长期读事务阻塞写入或 WAL 清理。FTS 与数据库落盘仍有内存成本；具体 cache_size、日志模式、checkpoint 和索引批次需按数据测量后记录，不把某个 PRAGMA 当全应用硬上限。[SQLite PRAGMA](https://www.sqlite.org/pragma.html#pragma_cache_size)

后台不反复扫描整个文件系统、联系人或 Notes。优先授权事件触发与必要检查点；剪贴板监测仅在 changeCount 变化时读取，不重复解码不变图片。监测频率、CPU 与唤醒次数需在 M1 实测，避免为记录历史建立高频忙轮询。

本地冲突与已注册通知不启动 Pi；默认不后台调用模型。索引、提炼、清理分批执行，有新前台任务时让出资源。面板隐藏停止不必要的动画和预览，Liquid Glass 使用系统效果，不自行持续截取壁纸模拟玻璃。

## 测量与验收

使用 Release 构建，在当前 Apple Silicon 设备记录系统、硬件、构建、Pi / Node 版本、数据规模和预热条件。分别记录原生主进程、Pi 与附属子进程的实际 footprint、CPU、启动时间和唤醒次数，不能只看 JavaScript heap、缓存记账或虚拟地址空间。

| 场景 | 检查重点 |
| --- | --- |
| 不用 AI 连续待机 24 小时 | 无 Pi 进程；主应用占用稳定，CPU 与唤醒可解释 |
| 面板开关 100 次 | 页面对象、监听与缓存不随次数增长 |
| 大图、长消息与大量历史 | 解码峰值、分页窗口、解析缓存、上下文与会话恢复有界 |
| 快速输入并取消查询 | 在途任务停止，迟到结果不写回，游标释放 |
| Pi 连续启停与异常退出 | 正常释放、无孤儿子进程、不重放写入 |
| 内存压力与权限撤销 | 可重建资源被清理，任务策略安全，普通入口继续响应 |

使用 Instruments Allocations、VM Tracker、Memory Graph 与 Leaks。没有泄漏报警不表示没有“仍可达但已无用”的缓存或单例数据；通过分代比较定位持续留存对象。[Apple 内存分析](https://developer.apple.com/videos/play/wwdc2024/10173/)、[Memory Graph 与 Allocations](https://developer.apple.com/documentation/xcode/gathering-information-about-memory-use)

验收关注资源引用确实结束、缓存不超预算、任务和监听数量有界，以及预热后重复同样操作回到稳定区间。分配器、系统与图形框架可能保留高水位缓存，不能要求释放对象后进程数值立刻精确回到首次启动值；持续增长仍必须解释和修复。

产品响应目标保留在 [PRD](PRD.md)：唤起可输入 P95 200 毫秒、本地首批结果 P95 100 毫秒、文件首批 P95 500 毫秒。Pi 冷启动、模型首字与请求耗时单独记录，不混进本地搜索指标。
