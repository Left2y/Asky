## 真实 Orca

运行以下显式启用的集成用例：

```sh
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer ASKY_ORCA_LIVE_TEST=1 swift test --package-path Packages/KulaCore --filter liveGitHubInstallAndOrcaHandoff
```

从公开 `Niall-Young/asky-plugin-orca` 仓库下载插件，在专用临时 Git 项目中通过 ToolService 创建独立 worktree、启动 Codex、发送测试 prompt，然后查询状态并提交后续消息。约 23 秒通过；提交与后续消息均返回原生 completed，插件阶段为 turn_started。仅证明交接与接收阶段，不将其描述为业务开发任务完成。

首次验收发现当前 Orca 的回执位于 `result.send.prompt`，插件错误地将接收标记为 unknown。修复后重新从 GitHub 安装并重跑通过。修复前后测试项目保留用于复核，没有修改用户项目。后续补充了终端不唯一时的显式选择接口，并通过独立插件的 10 项模拟测试。

实际结果 JSON 位于忽略的 build/plugin-live-*.json，包含本机临时路径，不提交这些原始日志。

## 分发与限制

- 检查 Debug 应用 Resources：没有 asky-plugin.json、Orca index.mjs 或插件 SKILL.md；官方插件位于独立仓库，没有加入主项目资源路径。
- 使用通用运行时完成协议 v2 hello/shutdown smoke 检查；发布脚本同步到 v2。
- 未生成 DMG/ZIP，未安装或发布新版 Asky。
- 任意第三方仓库、需要 npm 安装的真实插件与私有仓库不在本次真实验收范围；安装失败和依赖要求用模拟安装器验证，私有仓库暂不支持。
- 插件为可信用户代码，独立 Node 进程不提供系统沙箱。
