## M0 必须完成的验证

| 编号 | 验证 | 必需证据与决定 |
| --- | --- | --- |
| V01 | 原生外壳与视觉 | 快捷键、焦点、多屏、窗口隐藏与重内容释放；Light/Dark、不同壁纸、辅助功能与玻璃效果 |
| V02 | Pi 最小闭环 | Swift 提交请求、流式返回、一个原生工具及原生确认；记录实际 SDK / Node 版本与依赖 |
| V03 | 工具隔离 | 明确加载清单；默认编码、Shell、输入前缀、其他工具和全局资源不能绕过原生策略 |
| V04 | 进程生命周期 | 冷启动、启动请求合并、60 秒退出、等待确认保活、取消、崩溃与无孤儿进程 |
| V05 | 存储与恢复 | 对话唯一权威、投影修复、上下文有界、附件外置与彻底联动删除 |
| V06 | 兼容模型 | 文本、图像、流式工具参数、错误与取消分别验证；模型 Key 不额外持久化、不解释为命令；空闲不缓存保温或请求模型 |
| V07 | 系统适配器 | Chrome 排除无痕；Notes 授权范围与追加；Messages 正确目标、预填或复制回退 |
| V08 | MCP 与权限 | stdio Bridge、本地连接身份（当前为 Unix socket，见验证记录）、实例范围、确认拒绝、伪造确认、撤权与应用退出 |
| V09 | 资源基线 | 主进程和 Pi 的冷/热启动、实际内存峰值、退出后留存；判断预算与 Runtime 取舍 |

Pi 若无法满足恢复、隔离或资源门槛，先评估调整宿主与会话策略；仍不满足再评估 Agent Core 或纯 Swift 替代。不能在缺少测量时因语言偏好直接宣称某路线更省内存。

M0 冻结 IPC 承载与线格式、消息大小与背压、会话权威与导入方式、扩展清单、凭据注入及签名下的权限归属。既有概念接口不是已经存在的可编译 API。

## 性能验证流程

1. 在目标设备以 Release 构建记录系统与版本，建立冷启动、预热后待机与典型数据集基线。
2. 保持预先声明的数据规模，执行面板开关 100 次；记录留存页面、Task、监听器、缓存成本与 footprint。
3. 运行大图、长消息、长历史、快速查询与取消；测在途解码、协议与历史恢复峰值。
4. 运行 Pi 启停、等待确认、取消、网络失败、宿主或辅助进程异常退出；核查执行记录和系统结果。
5. 连续待机 24 小时，同时覆盖只用本地入口与实际 AI 使用；记录 CPU、唤醒、内存区间与进程状态。
6. 结合 Allocations 分代、Memory Graph、VM Tracker 与 Leaks 解释留存，复测修复涉及的场景。
7. 完成 M4 后连续使用 7 天，记录高频入口替代效果、重复解释、错误和提醒处理情况。

预热后的占用应进入稳定区间，不随循环次数持续上涨；缓存容量、活动查询、队列与监听数量必须有界。具体总内存、冷启动与耗电阈值基于原型测量后决定，不伪造测试结果。

## 风险与待验证记录

| 风险 | 当前设计与限制 |
| --- | --- |
| Pi 依赖与启动成本 | 允许列表只能减少加载，不能承诺消除全部依赖；按需启动并测实际资源 |
| Pi 持久化与原生 SQLite 重复 | 唯一权威与可恢复投影必须先验证，避免两份全量历史 |
| 临时截图残留 | 清理文件之外还检查 Pi 记录、消息、摘要、缓存与 Base64 副本 |
| 后台 AI 关闭影响复杂建议 | 本地规则继续；模型提炼与复杂新建议延后，不能声称实时智能不受影响 |
| 模型兼容性不一致 | 分项能力检查；缺失能力禁用，不降级成不可预测执行 |
| 系统自动化与 TCC | 在稳定身份下验证真实操作和权限提示，不直接读私有数据库 |
| 签名、辅助程序与分发 | 完整自用版先本机运行；公开签名公证、安装包、更新、Intel / 旧系统另行规划 |
| 图像、框架和分配器高水位 | 分析留存与峰值，不以立即回到初始 footprint 作为唯一标准 |

每项实际验证记录日期、硬件与系统、构建和依赖版本、数据集、动作、预期、观测、结论和残余限制。首轮记录见 [M0 验证记录 2026-10-09](validation/2026-10-09-m0.md)：自动化测试通过，V01、V06、V07、V09 及全部 UI 验收尚未验证。后续记录放在 `docs/validation/`，不把文档链接检查当功能测试。
