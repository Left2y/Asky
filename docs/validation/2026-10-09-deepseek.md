# DeepSeek 配置与真实对话验证（2026-10-09）

本次使用用户提供的 DeepSeek API Key，在已有 Debug App 中配置并验证。记录不包含密钥；没有修改 App 或 AgentRuntime 源码。

## 本地配置

| 项目 | 值 |
| --- | --- |
| API 地址 | `https://api.deepseek.com` |
| 模型 | `deepseek-flash` |
| Keychain service | `app.kulahere.credentials` |
| Keychain account / credentialRef | `model-api-key` |
| 非敏感设置 | LocalStore 的 `model.config` |
| 能力状态 | 文本 `available`，工具与图像 `unknown` |

地址与模型名先核对了 [DeepSeek 官方接入文档](https://api-docs.deepseek.com/)，再通过该账户的 `/models` 响应确认。配置使用临时编译的本地辅助程序，复用项目已有 `LocalStore`、`Keychain` 和 `ModelConfiguration`；Key 通过 stdin 输入，辅助程序位于已忽略的 `build/deepseek-setup/`。

## 实际运行结果

| 检查 | 结果 |
| --- | --- |
| 使用提供的 Key 请求官方 `/models` | HTTP 200；返回 `deepseek-flash`、`deepseek-v4-pro` |
| Keychain 写入及回读 | 一致；输出不含 Key |
| `model.config` 写入及类型化回读 | 与上述地址、模型名及凭据引用一致 |
| App › AI 对话提交“你好” | 经 App、AgentHost 与 Pi Runtime 返回真实模型回答，任务结束后发送框恢复空闲 |
| 新对话后从侧栏重开“你好” | 已保存的用户消息和模型回答重新显示；配置前的临时错误不再显示 |
| `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swift test`（`Packages/KulaCore`） | 102 个测试、20 个 suite 通过 |
| 密钥落盘检查 | 发现剪贴板历史中有一条记录包含该 Key；仅遮盖这条记录中的 Key，更新全文索引并完成 WAL checkpoint。随后检查 138 个文件，包括 Git 跟踪文件、临时辅助程序和应用数据文件，均未发现该 Key 的明文 |

仅将真实 App 对话已验证的文本能力标记为可用；本次没有运行设置页的三项能力探针。
