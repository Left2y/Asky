# 实际 Debug 列表拖放飞书文字验证（2026-10-18）

## 用户复现与原因

用户从左侧列表条目拖动文字到飞书时失败。确认其运行的是 `build/DerivedData/Build/Products/Debug/Asky.app`，已包含前次改动，并非旧版 Release。

在同一个正式 Debug 应用的默认列表布局中创建一条可清理的 AskyDragProbe 测试记录，使用真实 WindowServer 鼠标拖放复现。飞书空输入框暴露的 AXTextArea 为 `(402,795,772,22)`，文字包装层为 `(398,795,787,34)`，输入容器为 `(389,782,1055,48)`。拖到 `(1100,790)` 时原生返回 copy，但输入内容没有变化。

原因包括：

- 每 150 ms 采样可能错过最后进入窄输入区的鼠标移动，无法记录拖放前内容。
- 只接受文字行边界，没有识别空输入区的垂直留白；命中的背景 group 也需要找到实际 text area。
- 固定的非激活面板仍可持有键盘焦点；仅激活已经处于前台的飞书不能释放该焦点。恢复面板早于异步 Cmd V 投递也会使 Web 编辑器失焦。

## 修改

拖动观察改为逐个 movedTo 事件处理，提前排除本进程及非飞书应用，找到有效快照后停止观察。空输入区只扩展到附近容器的垂直留白，保持文字包装层的水平范围，排除右侧发送及其他控件。固定面板先隐藏以释放键盘焦点，投递后再等待 150 ms 恢复显示，不重新抢占 key window。

## 实际结果

- 正式 Debug、左侧列表、固定窗口、飞书空输入区留白 `(1100,790)`：通过。实际源进程日志显示原生 copy、识别到飞书、补粘贴 posted；随后在飞书 AX 树中读到单次 AskyDragProbe。固定面板仍存在。测试文字已删除，未发送消息。
- 同一个正式 Debug、左侧列表、未固定、飞书窄文字行 `(1100,805)`：通过。松手前命中 PID 确认为飞书，原生 copy 后补粘贴；界面再次读到单次 AskyDragProbe，源面板关闭。测试文字已删除。
- 修复前失败、仅 posted、被其他回归窗口遮挡或自动化未结束拖拽的尝试均不记为通过。
- Xcode 工程重新生成及标准 DerivedData Debug 构建、严格代码签名验证：通过。
- KulaCore `swift test`：通过，包括真实空输入区几何的留白、按钮、上下边界及不向整个窗口扩展检查。
- 拒绝原生拖放的独立接收进程回归增加 `--list-drag` 和 `--pinned-drag`，核对一次 DROP、取消及按钮无副作用、固定窗口保留但不保持键盘焦点。`--drag-paste-target --list-drag --pinned-drag` 与 `--drag-paste-target --list-drag` 均已实际运行通过。

为隔离并行构建，回归宿主在 `build/EmptyComposerRegression` 链接标准 Debug 的实际 App/module 对象；真实应用检查使用正式签名的 Debug 应用，不以临时卡片宿主代替。产物沿用既有 `build/` 忽略规则。最后删除本次单条测试记录，并正常重启已更新的 Debug。
