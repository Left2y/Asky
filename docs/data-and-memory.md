# Asky 数据、记忆与提醒设计

更新日期：2026 年 10 月 13 日。状态：记忆文件、显式工具、自动提炼与整理由当前实现核对；会话恢复及其他数据生命周期要求仍需按验证记录验收。使用步骤见[使用教程](https://asky.niallyoung2002.workers.dev/docs)。

数据默认留在设备上。只有被允许用于 AI 的必要上下文才发送到用户配置的模型；本地存储不表示离线推理。产品行为见 [PRD](PRD.md)，模型与会话整合见 [Agent Runtime](agent-runtime.md)。

## 数据归属

| 数据 | 权威来源与职责 | 原生读取方式 |
| --- | --- | --- |
| 日历、提醒、联系人、Notes | 系统应用继续为真实记录来源 | 授权范围内查询与有限快照，不全量复制私有数据库 |
| 活动、执行记录、提醒计划、授权设置 | 原生 LocalStore，SQLite | 分页、过滤和局部更新 |
| 当前个人记忆 | `Memory/MEMORY.md` 与同目录主题文件 | 索引随请求提供，主题按需读取；旧 SQLite 记忆仅用于兼容迁移 |
| 对话历史 | Pi 与 SQLite 的唯一权威方案必须经 M0 固化 | UI 使用分页显示投影，不加载全部 Runtime 消息 |
| 图片附件与大输出 | 独立本地文件，数据库保存引用与生命周期 | 使用时读入、显示缩略图 |
| API Key 与接入凭据 | Keychain | 仅调用方按需读取，不进入业务导出或日志 |

个人记忆当前采用 Markdown 索引与主题读取，不要求向量数据库、云端 embedding 或下载本地大模型。SQLite 仍承担其他产品数据与索引。文件名搜索交给 Spotlight，而不是为整盘内容另建全文索引。[SQLite FTS5](https://www.sqlite.org/fts5.html)、[Apple Spotlight](https://developer.apple.com/documentation/foundation/spotlight)

SQLite 存储落盘不代表可以无限缓存查询结果。连接、页缓存、索引更新、游标与结果集也需要有界管理，详见 [资源生命周期](resource-lifecycle.md)。

## 对话与 Pi 的整合决策

当前优先验证 Pi SessionManager 管理运行会话，SQLite 保存 UI / 检索投影、关联和产品数据的方式。投影必须可从选定的权威历史恢复，不能成为另一套互相矛盾的完整对话。

M0 必须核实：

1. 明确消息、分支、压缩摘要和完成状态的唯一权威来源，以及进程退出前保存的顺序。
2. 原生界面在 Pi 未运行时可以分页查看历史；切换会话不加载所有消息。
3. 宿主崩溃、Pi 崩溃和投影未完成时能够恢复，不重复消息或重放写入。
4. 恢复只装配任务需要的有界上下文；长会话文件解析也纳入内存测量。
5. 图片能外置并按需参与请求，清理附件后原始会话、投影、压缩摘要和引用不残留可恢复原图。
6. 对话删除、导出和授权撤销覆盖所有持久化载体，不只删 SQLite 的显示记录。

若 SDK 的会话模型不能满足这些条件，应验证受控会话段、导入或替代存储适配方式，再决定实现。不能先宣称 SQLite 与 Pi 都保存完整历史、以后再同步。Pi SessionManager 对运行上下文的权威规则需遵守，直接改 agent 内存消息不等同于修改已保存历史。[Pi Session storage](https://pi.dev/docs/latest/sdk)

## 当前记忆文件与接口

`MemoryFolder` 位于业务数据目录的 `Memory/` 下。`MEMORY.md` 是简短索引，包含“关于我”“偏好”“主题文件”；主题细节保存在同目录的 Markdown 文件中。索引提供给对话的上限为 6,000 字符，单次主题读取上限为 12,000 字符。当前文件不保存逐条确认、固定、来源引用或替代链；旧版记忆列表与基于 MemoryRecord 的说明不再适用于当前个人记忆。

首次索引不存在时，迁入旧 SQLite 中 active、已确认或固定、且允许 AI 使用的记录：偏好进入索引“偏好”，项目进入 `projects.md`，其他内容进入“关于我”。旧数据库记录不会因此被删除；仅删除索引可能触发再次迁入。

| 工具 | 当前行为 |
| --- | --- |
| `memory_read` | 读取指定记忆文件，主题按需读取 |
| `memory_save` | 向索引分组或主题追加内容，新主题登记索引链接；相同文字不重复添加 |
| `memory_correct` | 替换文件中唯一匹配的原文，不保留逐条替代关系 |
| `memory_forget` | 删除文件中唯一匹配文字所在的整行，不同步清理整理前副本 |

工具均经 ToolService，要求个人记忆来源已启用，不向外部 MCP 开放。默认自动审批模式下，用户明确要求的记忆写入直接执行；推断写入只作为建议。设置页提供“开启记忆”与“记忆文件”访达入口，用户可直接编辑文件。

### 自动提炼

对话结束后登记来源并按开关入队；结束一轮回复及新建对话时尝试消费。需要未暂停提炼、个人记忆来源启用、模型已配置且可无交互读取 Key。只处理空闲至少 30 分钟的对话，每次最多 3 个来源，增量使用上次处理位置之后的消息。

提示词只保留由用户明确表述的稳定事实、长期偏好、持续数周以上的项目或目标，优先返回空结果。不把一次工具使用泛化为长期习惯，不保存临时日程、待办、网页第三方内容、助理推测或敏感凭据。模型可追加、原文替换及删行，每类每个来源最多 3 项；失败重新入队，来源在请求期间被删除或失去提炼权限则丢弃结果。

提炼请求包含新消息、索引及有界主题内容（主题总预算 8,000 字符），发送至用户配置的模型。当前只自动提炼应用内对话，剪贴板、搜索和系统源不会被此流程全量收集为长期记忆。

### 自动整理与备份

提炼修改文件后标记待整理；文件有变化或索引超过 6,000 字符时，两次整理尝试至少间隔 6 小时，并在同样的 AI 使用机会执行。它不是定时后台模型轮询，也不受情境提醒的“后台 AI 判断”开关控制。

整理请求包含整个记忆文件集合，总输入超过 40,000 字符时跳过。模型合并重复、保留较新说法、删除明显过时或临时内容、把细节移到主题文件；验证索引、文件名、长度与主题链接后应用完整新版本。不再输出的旧主题文件会被删除。

应用前把上一版写入隐藏的 `.previous/`，下一次整理覆盖该副本；它不是完整历史或安全擦除保证。模型失败或回复未通过校验时不应用。直接文件编辑与显式工具写入不一定触发待整理标记；索引过长仍可触发整理。

关闭“开启记忆”只暂停自动提炼、整理与新增入队，已保存记忆仍可作为对话上下文或被显式工具修改。关闭“个人记忆”来源才会同时停用上下文及工具。两个开关都不删除已有文件。

## 来源与外发限制

来源设置分别控制读取、AI 使用、自动提炼与后台提醒。Chrome 标签搜索缓存与剪贴板历史不自动成为长期记忆；浏览历史和网页行为不进入首版采集范围；短信原文不做持久采集，仅在用户单独开启后由后台 AI 提炼成短事项（见下文）。

来源权限继承是系统资料与派生数据的设计要求。当前 Markdown 记忆不保存逐条来源权限，文件内容受整体“个人记忆”来源开关控制；不能声称已有逐条撤权联动。撤权后取消未执行的访问和请求，已发送的数据不能描述为可以从远端撤回。

记忆提炼以允许来源为候选。默认不会为每次搜索、每次复制或每条事件启动模型；本地可先记录来源与显式偏好，模型提炼进入有界队列，在下次 AI 使用时分批处理。记忆提炼不要求开启后台 AI 判断；复杂提醒的后台模型调用由独立开关控制。

## 删除、过期与保留

以下为数据生命周期设计要求，并非全部已实现。当前 Markdown 记忆没有按 60 / 180 天清理、逐条固定或删除来源联动；只会由显式操作、文件编辑或模型整理更新。删除对话不保证清除来源、附件、运行时历史及派生记忆，删除记忆行不清除 `.previous/` 副本。当前用户操作边界以[隐私说明](../PRIVACY.md#6-你的控制与删除方式)为准。

以下磁盘默认值来自 [PRD 建议默认值](PRD.md)，与内存缓存预算无关。

| 数据 | 默认保留与清理 |
| --- | --- |
| 剪贴板 | 启用后默认保留 3 天，可选 8 小时、1 天、3 天、7 天、30 天；旧版固定项同样到期清理；容量建议 200 MiB，先清理未固定旧项 |
| 活动记录 | 搜索与操作保留 30 天 |
| 完整对话与独立记忆 | 保留至用户删除；完整不代表全部常驻内存 |
| 截图 | 默认临时，任务结束清理原图；主动保留的附件跟随对话 |
| 当前工具快照与上传缓冲 | 请求或任务结束释放；只保留允许的必要结果 |
| 系统计划 | 事件变更、已处理、禁用类别或依据删除时重新校验或取消 |

固定剪贴板占满容量时不能偷偷删除固定内容或继续无限存储；建议停止新增并提示用户管理容量，此细节在原型中验证。

主动删除来源时，清理仅由该来源形成的记忆、索引、摘要、附件及提醒依据，并设置必要的删除标识，防止未完成提炼任务从残留内容重建。用户主动固定的独立记忆可按界面说明保留，但展示来源已删除。

自然到期仅清理原始活动，保留已获准独立保存的记忆和最小来源元数据，并标记来源已过期。不能把到期与用户主动删除混为一谈。删除授权时明确处理已保存记忆的保留选择，失去有效依据的提醒取消。

删除与索引更新需要可恢复的清理流程；覆盖 Pi 历史、SQLite、附件、显示缓存和待处理队列。逻辑删除不等于承诺底层磁盘安全擦除，也不等于数据库文件立即缩小。

## 情境提醒与后台调度

Context Scheduler 监听已授权的数据变化、临近检查点、相关记忆变化以及系统恢复，先运行确定性规则，不持续模型轮询。队列按事件与原因去重、合并与淘汰过期候选，不保存无限事件快照。

| 场景 | 确定性部分 | 必要条件 |
| --- | --- | --- |
| 日程冲突 | 时间重叠、相邻日程间隔、有效路线与交通偏好 | 不自动移动原日程 |
| 出行准备 | 起终点、目标时间、路线 ETA、交通方式、缓冲 | 缺起点、地点或 ETA 时只提示检查路线，不编造精确时间 |
| 重要日期 | 临近日期、允许记忆、已处理状态 | 生日送礼必须有关系或既往意图依据，无物流数据不承诺到货 |

ReminderPlan 至少保存事件标识、原因、依据引用、触发时间与状态。默认生日提前 7 天检查，出行缓冲建议 10 分钟；建议每天最多 2 条、09:00–21:00 无声交付。用户明确设置的定时提醒不受智能建议数量限制。

### 后台 AI 建议

用户开启「后台 AI 判断」并配置模型后，每次重新校验时把未来 7 天的日程、未完成提醒事项（按截止时间排序，最多 60 条）和允许 AI 使用的相关记忆，以短编号（E/T/M）发给已配置的模型。模型只返回日历本身做不到的建议：需要提前准备的事项、日程与待办或记忆之间的关联与矛盾、临近截止却未安排时间的待办；没有值得提醒的事返回空。

每条建议必须锚定输入中的日程或待办，依据编号逐条校验，未知编号丢弃；触发时间不早于当前、不晚于锚定日程开始和 7 天视野。建议以 `insight` 类别进入同一 Scheduler，排在确定性规则之后，共享去重、每日上限、09:00–21:00 窗口和“关闭此类”。输入指纹不变时 6 小时内不重复调用，两次调用至少间隔 10 分钟；锚定对象变更或删除后缓存建议失效并取消。后台调用不弹出 Keychain 交互，读不到 Key 时跳过。短信内容默认不在输入范围内。

用户另外开启“让 AI 读取短信与 iMessage”、选择读取时间范围（最近 3 天默认、7 天或 30 天）并授予完全磁盘访问后，ToolService 的 `MessagesHistoryReader` 以只读方式打开 `~/Library/Messages/chat.db`，读取所选范围内至多 300 条消息（含用户自己发出的，标记为“我”），跳过表情回应与系统项。macOS 没有读取短信的公开接口，这是唯一途径，因此该能力不兼容 App Store 沙盒。读取后立即脱敏：含验证码等字样的消息整条丢弃，8 位以上数字只保留后 4 位，每条最多 300 字；发送者优先显示通讯录姓名，否则手机号只显示尾号、邮箱只保留首字母和域名。`attributedBody` 按 typedstream 结构手工解析，不反归档对象。

短信分两步使用，避免单次请求过大。第一步 `MessageTriage` 只处理水位线（已读过的最大消息 ROWID）之后的新消息，按时间顺序每批约 2,500 字，附带同一会话前 3 条消息作上下文，请模型摘出仍需行动的事项（每条不超过 40 字，可带截止时间），并可把已完成、取消的旧事项标为已解决。每批成功后水位线前移，所以每条消息只发送一次；单轮最多 6 批，首次开启时其余历史在后续轮次读完，失败时从第一未读批继续。事项至多保留 30 条，超出所选时间范围自动丢弃。第二步 `SmartAdvisor` 只收到这些事项（S 编号），不再接触短信原文；事项可作为建议锚点，消失后对应缓存建议失效。事项摘要与水位线保存在本地设置中，短信原文不写入本地数据库或记忆；关闭该开关时清空事项与水位线。

短信中的明确会议、预约和出行可额外提取 `calendarDraft`（标题、开始时间、可选结束时间与地点），截止事项不能把截止时间作为日程开始时间。字段仍是模型候选：卡片提供“创建日程”，在共享应用弹窗中编辑并确认后，经 ToolService 的 `calendar_create_event` 写入和回读；取消或失败保留卡片。未给出结束时间时，弹窗明确提示暂按 1 小时预填。无效或已过期候选不提供创建入口，同名同开始时间的已有日程与重复短信候选会被过滤；实际写入仍按现有接口检查冲突，不自动覆盖或允许冲突。

旧摘要在首次升级时按已授权范围重新提取一次，随后仍按水位线增量处理。候选字段参与缓存指纹，改期、取消或候选消失后旧建议失效。创建请求在写入前持久化，连续点击合并；重启后重试沿用同一请求 ID，未知结果不盲目新建。只有 ToolService 确认完成并回读后才标记已处理并移除对应短信事项。后台提取不会直接创建日程。

默认后台模型唤醒关闭：本地冲突检查、已形成的路线计划与自绘提醒卡片照常运行；需要模型的新复杂建议等待下一次明确 AI 使用，或由用户单独启用后台 AI。不得为了按需省内存而声称所有智能建议仍可即时产生。

地图请求只发送必要地点，单独启用，不持续采集位置。计划由运行中的 Asky 通过右上角自绘卡片交付，无需系统通知权限、不进入通知中心。主应用退出后不交付提醒，也不发现新变化。启动、唤醒、时区变化、事件修改或删除时重新校验，取消过期计划。
